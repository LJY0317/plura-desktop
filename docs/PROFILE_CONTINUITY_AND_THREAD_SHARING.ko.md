# 로컬 프로필·계정 전환·Remote 연속성 및 대화 공유의 검증 경계

**상태: 기존 동작/사용자 관찰 정리 및 읽기 전용 진단 통합. 교차 계정 공유 기능은 미출시.**

## 사용자가 확인한 사용 경험 (독립적인 공식 API 검증과 구분)

동일 macOS에 기본 프로필 1과 Plura 관리 프로필 2가 있으며, A/B는
서로 다른 ChatGPT 계정을 가리킨다. 실제 계정 정보는 기록하지 않는다.

1. **같은 프로필 내 로그인 전환:** 프로필 1/A에서 만든 로컬
   Work/Codex 대화를 보존한 채 A에서 로그아웃하고 B로 로그인해도
   **같은 프로필에 남은 원본 대화**를 이어서 사용할 수 있었다고 한다.
   계정 전환 시 기존 대화를 자동 삭제하거나 재생성하는 동작을
   의도하지 않는다.
2. **사용량 귀속:** 계정 A에서 시작한 로컬 작업이라도 후속 턴의
   사용량/토큰 비용은 **현재 실행 시 로그인한 계정**에 귀속된다는
   사용자 설명이 있다. 이는 관찰/이전 안내의 기록이며,
   실제 과금 원장·엔타이틀먼트·공식 청구 계약을 독립 검증한
   사실이 아니다.
3. **동일 계정의 복수 Remote:** 프로필 1/A에 iPhone/A와 iPad/A를
   동시에 공식 모바일 Remote로 연결해서 사용할 수 있었다고 한다.
4. **프로필별 독립 Remote:** 프로필 1/A와 프로필 2/B는 서로 다른
   로그인과 공식 모바일 Remote 연결을 동시에 유지할 수 있다.
5. **순차 계정 전환 후 모바일 연속성:** 프로필 1/A에서 진행하던
   로컬 대화를 유지한 채 데스크톱 프로필 1과 iPhone을 모두 B로
   로그인 전환했을 때, iPhone/B의 공식 Remote에서도 **프로필 1의
   원본 대화**를 다시 열고 이어서 작업할 수 있었다고 한다.
6. **Work/Codex UI:** 사용자는 로컬 Work와 Codex 대화가 데스크톱의
   같은 사이드바 범주·대화 표시·재개 UX를 사용하는 것으로
   관찰한다. 이 UI 유사성은 두 종류의 대화 저장/실행/계정/클라우드
   프로토콜까지 같다는 증거가 아니다. 제품 내부 구현은 별도 확인한다.

**중요한 구분:** 위 1·5는 **같은 프로필에서 A→B로 순차 로그인
전환한 연속성**이다. 목표인 **프로필 1/A와 프로필 2/B가 서로 다른
계정으로 동시에 로그인한 상태에서 동일한 원본 대화 하나를 공동
제어**하는 기능이 이미 제공된다는 뜻이 아니다.

## 코드·격리 실험으로 확인한 범위

- 기본/관리 프로필은 `CODEX_HOME`과 Electron 사용자 데이터 루트를
  별도로 사용한다. 프로필별 저장소와 실행 상태는 자동으로 하나의
  원본 대화로 병합되지 않는다.
- 격리된 임시 `CODEX_HOME`에서 공식 Codex App Server
  **하나에 두 WebSocket 클라이언트를 연결**해 동일 T를 읽고,
  순차 턴 생성·알림·진행 중 steer·재연결을 검증했다.
  이는 **서로 다른 실제 계정/모바일 Remote/Work 사용 검증이 아니다.**
- 원본 App Server에 무제한으로 두 번째 클라이언트를 붙이면
  **공유하지 않은 비공개 대화 P까지 노출**될 수 있었다.
  따라서 전체 소켓·대화 인덱스·DB·JSONL을 공유하는 방식은
  기능 제공 방식으로 채택하지 않는다.
- 공식 모바일 Remote 수신 요청은 해당 계정의 App Server로
  직접 들어간다. 현재 확인한 공개 프로토콜로는 다른 계정의
  원본 스레드 T만 안전하게 찾아서 접근권을 받고 owner A로
  위임하는 엔드투엔드 기능이 확보되지 않았다.

## 제품 설계 결정

**선택한 대화 T의 실행 상태에 대해서만 원본 owner A를 유일한
writer로 유지**하고, 프로필 B의 독립 로그인·App Server·모바일
Remote 등록은 그대로 보존한다. A가 B에게 T 하나를 명시적으로
승인하는 계정 검증·권한 철회·목록 발견·완전한 history replay·
활성 이벤트·turn/steer 위임이 **공식적으로 지원될 때**에만
동시 대화 공유 기능을 활성화한다.

ChatGPT Work에는 Codex의 로컬 App Server 테스트를 그대로
대입하지 않는다. Work가 Codex와 비슷한 사이드바에 보이더라도
소유권/권한/Remote/클라우드 기록 경계는 별도 확인해야 한다.
현재 구현된 사용자 기능과 미래 설계 후보를 혼동하지 않는다.

## 개인정보를 읽지 않는 로컬 분리 진단

```sh
python3 scripts/diagnose_local_conversation_isolation.py
python3 -m unittest discover -s tests -p test_local_conversation_isolation.py -v
```

macOS의 알려진 기본·프로필 2 경로에서 디렉터리·파일의 존재,
inode 동등성, 링크, 설치 ID의 **값 비노출 동일성 판정**과
rollout 파일 개수만 확인한다. **대화 본문, 로그인 토큰, 쿠키,
브라우저 DB 원문, 계정 ID, Remote 등록 내용은 읽지 않는다.**
출력은 한 시점의 저장소 물리 분리 상태만 보여주며 특정 Work
대화가 동기화되는지, 원본 ID가 겹치는지, 상대 계정의 권한이
있는지까지 주장하지 않는다.

종료 코드: `0`=검사 범위에서 분리 확인,
`2`=경로/자료가 누락되거나 미확인, `3`=같은 물리 저장소 또는
안전하지 않은 링크·설치 ID 재사용 의심. 이 도구는 **읽기 전용**이며
이상 상태를 자동으로 수정하지 않는다. 저장 형식·앱 버전이
변하면 알려진 경로의 탐지 범위를 다시 검증한다.

## 남은 기술 게이트

권한 있는 소스/클라이언트의 스레드별 계정 검증, 공유 허가·철회,
비공개 P 완전 비노출, 모바일 B→B App Server→원본 owner A의
안전한 라우팅, 삭제/되돌리기/압축/첨부/권한·모델 사용량 정책,
양쪽 Desktop·Remote의 동시 알림/재동기화 및 실제 계정 opt-in
검증이 끝나기 전에는 교차 계정 공유 UI를 배포하지 않는다.
